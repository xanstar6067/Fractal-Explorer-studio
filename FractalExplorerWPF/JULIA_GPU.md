# Жюлиа: GPU и живой выбор C

WPF-режимы «Классическое множество Жюлиа» и «Горящий корабль (Жюлиа)» автоматически
вычисляют орбиты на аппаратном Direct3D 11 при зуме ≤1e6 и до 4096 итераций.
Карта исходного множества в отдельном окне выбора C выбирает движок независимо;
её зум теперь достигает 1e12. Большее число итераций, более глубокий зум или
недоступность GPU переводят соответствующий вид на штатный ЦП. При уменьшении
зума GPU возвращается; неисправное устройство повторно не вызывается до открытия окна.

Кнопка «Применить» обновляет C и оставляет окно открытым. Повторное открытие
активирует существующее окно; основное окно остаётся доступным.
Галочка «Живой просмотр» позволяет выбирать C, удерживая левую кнопку мыши.
Одновременно считается один кадр, новое положение заменяет ожидающее положение.
Каждый живой кадр строится в полном размере с выбранным SSAA, без уменьшения
разрешения или числа итераций. Если рендер не успевает за мышью, пропускаются
промежуточные положения C; качество кадра сохраняется. Отпускание кнопки
или потеря захвата мыши применяет последнюю точку с теми же настройками качества.
Без галочки выбирайте точку и нажимайте «Применить».

Когда основное изображение считается на ЦП, живое перетаскивание меняет маркер
и числовые поля в карте, но основной вид обновляется только после отпускания кнопки.
Пояснение показано рядом с галочкой. Карта при этом может оставаться на GPU;
обратное сочетание (ЦП-карта и ГП-Жюлиа) также работает.

## Точность и ресурсы

`MandelbrotPreviewRenderer` принадлежит одному виду. Двумерные оси координат
готовятся в decimal как в штатном рендерере, орбиты считаются в double на GPU;
`precise` запрещает слияние умножений и сложений, способное менять ветви корабля.
Вычисления разбиты на полосы по 32 строки с отменой между полосами.
Трансцендентные метрики окраски читаются в float32; палитры, гамма, гистограмма,
ловушка, полосы, полиномиальная окраска и рельеф используют общую CPU-реализацию.
Небольшие цветовые различия на границе множества возможны.
Экспорт и превью сохранений продолжают использовать штатный точный CPU-рендер.

Шейдер `julia-preview-metrics` участвует в общем дисковом кэше и команде
«Пересобрать шейдеры». Ошибка создания/расчёта GPU отменяет его использование
в данном виде, пишет причину в журнал и возвращает расчёт на ЦП.
Закрытие окна отменяет работу и освобождает GPU-ресурсы в фоне.

## Проверка

```powershell
dotnet build .\FractalExplorerWPF\FractalExplorerWPF\FractalExplorerWPF.slnx
dotnet run --project .\FractalExplorerWPF\Verification\SavePreviewVerification.csproj -- julia-gpu
dotnet run --project .\FractalExplorerWPF\Verification\SavePreviewVerification.csproj -- shadercache
```

`julia-gpu` сравнивает все семь окрасок двух Жюлиа и двух карт с CPU-эталоном,
проверяет отмену, отказ GPU, границу зума, повторное применение, отсутствие очереди
живых кадров, полное разрешение и идентичность живого/завершённого кадра с SSAA и оба сочетания CPU/GPU главного вида и карты.
Окна открываются вне экрана, пользовательские данные перенаправляются в тестовую папку.

Ручная проверка: откройте оба режима, несколько раз примените разные C, включите
галочку и поводите с зажатой левой кнопкой. Проверьте, что во время движения сохраняются полное разрешение и выбранное SSAA.
Отпустите кнопку: кадр должен соответствовать последнему положению C.
Пока выбор C открыт, приблизьте основной вид выше 1e6: перетаскивание должно
применять C лишь после отпускания. Уменьшите зум и проверьте возврат живого просмотра.
Приблизьте саму карту выше 1e6; проверьте CPU-карту, колесо и перемещение средней
кнопкой, затем сбросьте вид. Закройте основное окно во время перетаскивания.

## Старые сохранения Жюлиа

Формат 5 восстанавливает старые поля `CRe`/`CIm` как `JuliaCReal`/`JuliaCImaginary`
для обеих Жюлиа. Современные поля, включая явно заданный ноль, имеют приоритет.
Преобразование происходит в памяти при чтении; оригинальный JSON записывается
в новом формате только при явном сохранении. Старый импорт, который ставит
текущую версию без переименования полей, тоже поддерживается.
Если сохранение содержит только имя палитры, превью использует ту же палитру,
что и основной вид. Ранее записанное чёрное PNG-превью надо пересчитать кнопкой
«Рендер превью» после обновления приложения; автоматически пользовательские
превью не пересчитываются.

Проверка: `dotnet run --project .\FractalExplorerWPF\Verification\SavePreviewVerification.csproj -- julia-saves`.
