# Числовой ввод WPF

Новые и изменяемые числовые поля подключаются к `Controls/NumericInput.cs`. Наличие стрелок
`NumericSpinner` само по себе не задаёт ограничений. Проверки состояния и движка остаются
защитой для загрузки сохранений и других источников данных.

## Контракт

- Во время набора допускаются пустая строка, `-`, `1e-` и другие черновики. `TextChanged`
  показывает подсказку у поля, но не переписывает его текст.
- На потере клавиатурного фокуса, Enter и перед явным применением число ограничивается
  диапазоном. Пустой, непарсящийся и неконечный ввод восстанавливает последнее корректное
  значение. Начальные значения, загрузка и пресеты устанавливают корректную точку возврата.
- Исправление видно в тексте поля. Рамка и подсказка объясняют причину; статус окна не является
  единственным местом ошибки. Escape восстанавливает последнее корректное значение.
- После исправления выполняется то же действие, которое запросил пользователь. Второго
  нажатия «Построить» не требуется. Обработчики должны объединять запросы кадра через
  существующий таймер/планировщик; параметры подготовки симуляции не перезапускают её при наборе.
- Неактивные параметры не должны останавливать активный расчёт. При чтении старых общих DTO
  их неправильные черновики восстанавливаются; применимость задаётся логикой режима, а не
  раскрытием `Expander`. Несовместимые пары границ восстанавливаются вместе.
- Тип соответствует потребителю: целые, `double`, точные `decimal`, `FloatExp` для глубокого
  масштаба. Корректные десятичные координаты и научная запись не проходят через `double`
  ради форматирования. Запятая и точка поддерживаются независимо от культуры интерфейса.
- Формулы, правила L-систем и сложные математические ограничения требуют собственного
  сообщения рядом с редактором. Подставлять предполагаемую формулу автоматически нельзя.

## Подключение

После установки начального состояния окна или контрола:

```csharp
NumericInput.Integer(this, IterationsBox, "Итерации", 50, 2_000_000);
NumericInput.Real(this, GammaBox, "Гамма", 0.1, 5);
NumericInput.Decimal(this, JuliaRealBox, "Re C", -10m, 10m);
NumericInput.Zoom(this, ZoomBox, MinZoom, MaxZoom, () => _viewport.Zoom); // границы FloatExp
NumericInput.Integer(this, GridSizeBox, "Размер сетки", 201, 1401, step: 2);
NumericInput.OrderedPair(this, MinimumBox, MaximumBox); // оба поля уже зарегистрированы
```

Для диапазона, зависящего от выбранного режима, `Integer` принимает функции минимума и
максимума. Повторная регистрация нужна только при замене самого контракта, а не на каждый кадр.

Автоматический захват параметров начинается с `NumericInput.Prepare(this)` — он не завершает
сфокусированный черновик. Явная команда построения, применения, экспорта или сохранения
начинается с `NumericInput.CommitAll(this)` до чтения полей. Живой обработчик, меняющий
внутреннюю модель непосредственно из текста, проверяет `NumericInput.IsValid(box)` перед
изменением модели. В конце загрузки связанные поля должны образовывать корректную пару.

Прямая привязка `TextBox.Text` к `Slider.Value` получает правила из `Minimum`/`Maximum`
ползунка при загрузке через общий стиль (`UseSliderBounds`). Для остальных полей регистрация
остаётся явной; стрелки не определяют диапазон.

Для немедленно применяемых масштаба и камеры передавайте `appliedValue`: возврат должен
брать фактическое значение модели, а не округлённое представление поля. Для текстовых
черновиков параметров подготовки симуляции сохраняется последнее корректное редактирование.

Область регистрации — окно или конкретный редактор. `Include(parent, editor)` включает
редактор в команды родителя без обхода визуального дерева на каждом кадре. Родительские команды должны завершать
ввод редакторов, чьи параметры они читают. Не регистрируйте произвольные текстовые поля по
имени или наличию стрелок; диапазоны определяет математическая модель.

## Проверка

`dotnet run --project .\FractalExplorerWPF\Verification\SavePreviewVerification.csproj -- numeric-input`

Группа работает без показа окон и пользовательских данных: черновики, потеря фокуса,
возврат/ограничение, культуры, пары, точность `decimal`, глубокий масштаб и захват параметров
подключённых окон. При подключении нового семейства расширяйте эту группу и проверки режима.

Исторический перечень проблем — [INPUT_VALIDATION_AUDIT.md](INPUT_VALIDATION_AUDIT.md).
Его исходные результаты описывают состояние до исправлений и не являются списком уже
подключённых элементов; актуальный охват фиксируется проверками и регистрациями `*.NumericInput.cs`.


## Охват внедрения

Подключены числовые параметры исследовательских WPF-окон, включая динамические системы,
лаборатории, все семейства Мандельброта/Жюлиа и общую панель 41 режима 3D; отдельные панели
всех десяти GPU-моделирований; числовые поля редакторов матриц IFS/Flame 2D/3D, палитр,
выбора C и генератора L-систем. Строки гибрида и масштабов Тьюринга регистрируются при
создании и исключаются из области при удалении.

Обычные числовые ограничения исправляются общим механизмом. Сложные ограничения модели
(например, допустимость формулы или геометрии) сохраняют собственные проверки и сообщения:
общий механизм не должен подменять математический смысл параметров догадкой.

Для вращения камеры полные обороты приводятся к эквивалентному углу; положительный масштаб
Flame сохраняет прежнюю интерпретацию отрицательного ввода как модуля. У полей, связанных
с ползунком, возврат использует фактическое значение ползунка с полной точностью, а границы
читаются заново при изменении его диапазона. Автозахват не записывает округлённый текст
обратно в источник привязки.
