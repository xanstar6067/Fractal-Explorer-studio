# Свифт–Хоэнберг 3D · пространственные узоры

WPF-каталог: **Динамические системы и хаос → Пространственные системы**.
Ключ `Fractal3D:SwiftHohenberg3D`, общее окно `Fractal3DWindow` и панель `SwiftHohenberg3DEditor`.

## Модель

Вещественное безразмерное поле в периодическом кубе:

```text
∂ₜφ = rφ − (q₀²+∇²)²φ + bφ² − φ³.
```

Кубический вариант получается при b = 0; квадратичный член нарушает симметрию φ ↔ −φ.
Линейный показатель роста моды k — `r−(q₀²−|k|²)²`, поэтому предпочитается
длина волны λ₀ = 2π/q₀. r управляет неустойчивостью, b — асимметрией фаз.
Основа модели: [квадратично-кубическое уравнение, Gandhi et al.](https://www.cbeaume.com/download/Gandhi_2015_SIAMJApplDynSys_A-new-resonance-mechanism.pdf).
В реализации одномерная производная заменена трёхмерным лапласианом и оставлен настраиваемый q₀.

Среднее поле не фиксируется: это обычная динамика Свифта–Хоэнберга.
В фазовом поле кристалла динамика имеет дополнительный лапласиан перед вариационной производной
и сохраняет среднее; такой режим этой реализацией не подменяется.

Свободная энергия непрерывной модели:

```text
E = ∫ [((q₀²+∇²)φ)²/2 − rφ²/2 − bφ³/3 + φ⁴/4] dV,
∂ₜφ = −δE/δφ.
```

## Расчёт на ГП

Весь расчёт и публикация объёма идут на общем устройстве Direct3D 11.
`GpuFft3D` одновременно преобразует φ и `bφ²−φ³`; после спектрального шага
обратное БПФ возвращает поле. Никакого чтения поля на ЦП между кадрами нет.
Порции по четыре целых шага, два слота публикации, отмена и сохранения — через `GpuVolumeSimulation`.
Упаковка скалярного поля, цикл БПФ, проекция и публикация вынесены в общий
`GpuSpectralScalarSimulation`, который также использует фазовое поле кристалла 3D.

Временной шаг ETD1, с L(k) = r−(q₀²−|k|²)²:

```text
φ̂ₙ₊₁ = exp(Δt L) φ̂ₙ + [exp(Δt L)−1]/L · FFT(bφₙ²−φₙ³).
```

Линейная часть интегрируется точно; около L = 0 коэффициент вычисляется рядом
с пределом Δt. Нелинейность явная, схема первого порядка по времени.
Точная линейная интеграция снимает жёсткое ограничение Δt ∼ Δx⁴,
но не делает нелинейный шаг безусловно устойчивым. Допустимы Δt 0,002–0,05;
для исследования точности сравнивайте результат с меньшим шагом.

Спектральная полоса: по каждой оси сохраняются целочисленные частоты `|m| < N/4`.
Для произведения трёх полей в этой полосе 4·max|m| < N, поэтому частоты,
обёрнутые дискретным преобразованием, не попадают обратно в сохраняемые моды.
Начальные поля и кисть проектируются в эту полосу; после каждого шага она сохраняется.
Состояние с диска загружается без дополнительной фильтрации, чтобы точно восстановить кадр.
Проекция означает, что эффективное разрешение ниже числа узлов; это не обрезка амплитуды.
Внешнее вручную созданное поле вне полосы не даёт той же гарантии отсутствия наложения частот на первом шаге.

Сетки 32³, 64³ и 128³, Δx 0,5–2; длина области N·Δx.
q₀ 0,4–1,5, с ограничением q₀·Δx ≤ 1,2, чтобы предпочтительная частота была внутри полосы.
r −0,5…1, b −1,5…1,5, начальный шум 0…0,3.
Изменение N при том же Δx меняет размер физической области.
Вычисления float32; контрольная точка отвергает нечисловые и чрезмерные значения |φ| > 3.
Все шесть вычислительных проходов, пиксельный шейдер и общий БПФ входят в дисковый кэш
и команду «Пересобрать шейдеры».

## Виды и управление

Семь готовых видов: лабиринт из шума, параллельные и наклонные слои,
шестигранные колонны, пространственная решётка, крупные ячейки, локальная затравка.
Начальное число делает шум воспроизводимым. Структурированные затравки используют
целые пространственные частоты и совместимы с периодическими границами.
Пресеты демонстрируют развитие выбранных затравок, а не обещают устойчивость конкретной
морфологии при произвольном изменении r, b и q₀.
По умолчанию шум проходит 500 шагов подготовки и встаёт на паузу.

- Положительная/отрицательная фаза: плотность `max(±φ/A,0)`.
- Границы: плотность `max(1−|φ|/A,0)`; высокий уровень выделяет область φ ≈ 0.
  У нулевого однородного поля эта область заполняет весь объём.
- A — «Масштаб поля для отображения»; он меняет только геометрию и окраску кадра.
- Окраска «По полю φ» показывает знак и величину; «По модулю |φ|» — величину без знака.
- Срезы X/Y/Z, девять общих стилей, палитры, камера, зонд и экспорт используют общий рендер объёмов.

Уравнение, сетка, затравка и шум применяются кнопкой «Применить и начать заново».
Неверный ввод сохраняет показанный кадр. Фаза, срез, уровень, палитра и скорость
не перезапускают поле. Пробел — продолжить/пауза, «Один кадр» — выбранное число шагов.
Экран подготовки закрывается первым актуальным кадром; остановка оставляет частичный снимок.

Кисть в центре или Shift+щелчок на срезе плавно задаёт +1, −1 или 0 в сфере.
Она оборачивается через периодические границы и затем проецируется в спектральную полосу,
поэтому затравка сглаживается и может иметь слабые боковые колебания. Номер шага не изменяется.

## Атлас параметров

«Атлас параметров…» в панели открывает `SwiftHohenberg3DAtlasWindow`.
По умолчанию оси — r и b; доступны q₀, Δx, Δt, масштаб показа поля A,
уровень поверхности и три именованных представления: положительная фаза,
отрицательная фаза и границы φ ≈ 0. Положение среза появляется при активной оси.
Число ячеек, затравка, начальный шум, seed, периодические границы и ось среза
фиксированы. Используется применённое уравнение, черновик основной панели
не участвует в сравнении.

Каждый вариант независимо продолжает один точный снимок φ показанного кадра
на 1–10 000 шагов (по умолчанию 48). Без снимка поле создаётся по исходным
q₀/Δx и один раз проецируется в спектральную полосу, затем фиксируется для
всех вариантов. Поэтому смена предпочтительной длины волны не пересоздаёт
структурированную затравку. Контрольная точка загружается без дополнительной
фильтрации. Сетка не уменьшается, подготовка `WarmupSteps` не повторяется;
поля всех ячеек не считываются и не накапливаются на ЦП.

q₀ задаёт предпочтительную λ₀ = 2π/q₀; при фиксированном числе ячеек Δx меняет
физическую область `Nячеек·Δx`, сохраняя начальный массив φ. Ячейка с
`q₀·Δx > 1,2` отключается с объяснением до расчёта (допуск 1e−12 совпадает
с `Validate`). Это ограничение спектральной полосы, не гарантия устойчивости
или точности нелинейного шага. Длительность прогона равна `Nшагов·Δt`;
для сравнения при равном времени оставьте Δt фиксированным.

Среднее φ свободно меняется. Вид, A, уровень и срез меняют только показ;
у нулевого поля представление границ φ ≈ 0 заполняет весь объём.
Короткий прогон не гарантирует длительной устойчивости выбранного узора.

Открытие ставит моделирование на паузу. Применение повторяет выбранный прогон
и переносит точное знаковое поле с номером шага на паузе, сохраняя камеру,
оформление и темп продолжения. «Вернуть предыдущий» восстанавливает исходное
поле, уравнение и вид; история хранит до четырёх записей до закрытия окна.
Остановка/закрытие отменяют незавершённое применение. Закрытие без применения
сохраняет исходный снимок. Числа проходят `NumericInput`; коэффициенты
основной панели показываются с точностью round-trip.

## Сохранения и файлы

`Saves/Fractal3DSwiftHohenberg/`: общий JSON + PNG через `Fractal3DSaveStore`.
Знаковое поле и номер шага сохраняются без потерь в Brotli/base64 float32 с ограничением
распакованного размера. Поле хранит номер шага. После изменения Δt через атлас
произведение Step·Δt не отражает накопленное физическое время, поэтому панель и
описание сохранения показывают шаг и текущий Δt. При постоянном Δt с начала
прогона время равно Step·Δt; явное применение основной панели запускает новое поле.
GPU-ссылки в JSON не попадают; продолжение на том же ГП побитово совпадает.
Старые сохранения остальных режимов читают новое свойство с умолчанием, миграция не нужна.
Категория распознаётся общим облачным репозиторием; предел сервера 1 МиБ на JSON
сохраняется, большие контрольные точки могут быть доступны только локально.

Файлы: `Models/SwiftHohenberg3DSettings.cs`, `Models/Fractal3DModes/SwiftHohenberg3DMode.cs`,
`Controls/SwiftHohenberg3DEditor.xaml(.cs)`, `Core/Rendering3D/SwiftHohenberg3DGpuSimulation.cs`,
`SwiftHohenberg3DComputeShader.cs`, `Shaders/Volume.hlsl`,
`Infrastructure/Serialization/SwiftHohenberg3DFieldConverter.cs`.

## Проверка

```powershell
dotnet build .\FractalExplorerWPF\FractalExplorerWPF\FractalExplorerWPF.slnx
dotnet run --project .\FractalExplorerWPF\Verification\SavePreviewVerification.csproj -- swift-hohenberg3d [папка PNG]
```

Независимый прямой DFT в double, энергия, аналитические кубические гармоники для обеих
реализаций БПФ на всех сетках, линейные растущая/затухающая/нейтральная моды,
сходимость к однородному аналитическому решению, стационарное поле, изменение среднего,
полоса начального шума, длительные прогоны крайних параметров, три кисти,
слоты и устаревшие билеты, отмена, точность JSON/продолжения/хранилища, повреждённые данные,
облачная категория, пресеты с PNG, стили, фазы, срезы, зонд и скрытое WPF-окно.
Данные проверок перенаправлены в отдельную папку.

Адресная группа `swift-hohenberg3d-atlas` проверяет семь пресетов, активные срезы,
точные числа, три вида и границу q₀·Δx. Короткие прогоны 32³ семи затравок при
смене q₀/Δx сверяются с прямым GPU-расчётом от одного уже проецированного поля
и JSON. Проверяются полностью недоступная и смешанная сетки, именованная ось
представления, совпадение миниатюр трёх видов, масштаб показа без изменения φ,
точные знаковое поле/шаг, перенос на паузе, сохранение, возврат, отмена/закрытие.
Длительная группа вычислительного ядра не запускается.
