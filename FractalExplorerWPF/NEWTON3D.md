# Ньютон 3D: бикомплексные бассейны

Пункт «Фракталы → Трёхмерные фракталы → Ньютон 3D» открывается в общем
`Fractal3DWindow`. Это трёхмерный срез четырёхмерного фрактала Ньютона,
а не рельеф плоского изображения. Камера, девять стилей, палитры, подготовка,
сохранения, облако, экспорт и зонд поверхности общие с остальными 3D-режимами.

## Математическая модель

Бикомплексное число `q = x + iy + jz + ijw`: `i² = j² = −1`, `ij = ji`.
Для `P(q) = qⁿ − 1` используется итерация

```text
q ← q − α P(q) / P′(q),     P′(q) = n qⁿ⁻¹.
```

В идемпотентном базисе компоненты независимы:

```text
q+ = (x+w) + i(y−z)
q− = (x−w) + i(y+z)
```

Каждая проходит обычный комплексный Ньютон для `zⁿ − 1`. Корни нумеруются
по углу `2πk/n`, начиная с положительной вещественной оси. Бикомплексному
корню соответствует упорядоченная пара корней компонент: всего `n²`.
Пара существует, только когда сошлись обе компоненты. Нулевая производная
в любой компоненте соответствует необратимой бикомплексной производной:
она не заменяется искусственным малым числом.

Основа обобщения — [Baieri и др., Newton’s Fractals on Surfaces via Bicomplex Algebra](https://dbaieri.github.io/publication/newton).
Режим использует собственную визуализацию среза и не воспроизводит
неописанный алгоритм изображений Jos Leys.

## Что отображается

Три пространственные координаты задают `x,y,z`, а `w` фиксируется полем
«Координата 4D-среза». Область — куб `[−extent, extent]³`; изображаемый куб
нормирован к `[−1,1]³`, поэтому изменение полуразмера меняет область исследования.

- **Границы · медленная сходимость** — приближение окрестности границы по числу
  итераций более медленной компоненты. Порог и разрешение управляют толщиной
  видимой структуры. Это не точная функция расстояния и не доказательство
  расходимости: в слой входят точки, не сошедшиеся за заданный бюджет.
- **Один бассейн компоненты +** — все точки, у которых компонента `q+` сошлась
  к выбранному корню; судьба второй компоненты на эту маску не влияет.
- **Пересечение · пара корней** — точки, в которых обе компоненты сошлись
  к указанной паре. Можно выделить одну пространственную область.
- **Отсечение по X/Y/Z** открывает внутреннее строение. **Только цветная плоскость**
  показывает исходные данные на плоскости независимо от выбранной маски области.
  При `w=0,z=0` компоненты совпадают: получается классический комплексный Ньютон.

Окраски: пара корней, корень +, корень −, скорость сходимости, а также общие
материал, нормаль, глубина и другие. Номера корней читаются ближайшим текселем,
без интерполяции категорий; плотность фильтруется линейно.

## Численные пределы и производительность

Степень 3–8; бюджет 16–128 шагов; действительная релаксация 0,2–1,8;
сетки 32³, 64³, 96³, 128³, 192³. Критерий каждой компоненты: `|zⁿ−1| < 10⁻⁵`.
Деление прекращается при `|P′|² < 10⁻²⁴`, `|P′|² > 10³⁰`, компоненте `z` за
пределами ±10⁶ или нечисловом результате. Последняя проверка сходимости
выполняется и после последнего разрешённого шага.

`Newton3DCompute.hlsl` считает поле на Direct3D 11 по четыре плоскости за dispatch;
ожидание ограничено тайм-аутом, между плоскостями работает отмена. Поле float4
хранит маску, индекс корня +, нормированное число итераций и индекс корня −.
Максимальная текстура 192³ занимает 108 MiB. Рендер идёт через ветвь
`VOLUME_KIND == KIND_Newton3D` общего `Volume.hlsl`.

Камера, цвет, освещение, отсечение и плоскость не пересчитывают поле. Изменение
формулы, координаты w, сетки или маски строит новую текстуру; публикация — только
после полного завершения. Отмена сохраняет предыдущую готовую текстуру.
Байткод обоих шейдеров находится в общем кэше, варианты участвуют в
«Пересобрать шейдеры». Данные пользователя проверками не затрагиваются.

## Проверка

```powershell
dotnet build .\FractalExplorerWPF\FractalExplorerWPF\FractalExplorerWPF.slnx
dotnet run --project .\FractalExplorerWPF\Verification\SavePreviewVerification.csproj -- newton3d
```

Группа сравнивает GPU с независимыми double-орбитами через `Complex.Pow`,
проверяет бикомплексное умножение по четырём компонентам, все сетки, шесть
пресетов, стили и цвета, сечения и зонд, отмену без публикации частичного поля,
переиспользование, JSON/облако, точность полей WPF и закрытие подготовки.
PNG пресетов и панели пишутся в отдельный каталог проверки; вторым аргументом
можно указать другую папку.

Ручная проверка:

1. Открыть режим: до первого кадра видна подготовка, затем цветные поверхности.
2. Изменить `w`, степень и релаксацию: структура должна меняться; отмена доступна.
3. Переключить бассейн и пару, выбрать разные корни; вращать и приближать камеру.
4. Подвигать отсечение по трём осям и включить плоское сечение.
5. Выбрать последний пресет: плоскость должна показывать классический Ньютон.
6. Сохранить вид с дробными параметрами, открыть его заново и экспортировать PNG.
