# FractalCloud в WPF

В главном окне нажмите **«Облачные сохранения…»**, либо **«Облако…»** в менеджере сохранений любого фрактала. Если сеанса нет, окно само показывает форму входа: email и пароль существующего пользователя. Регистрация не предлагается. После перезапуска вход восстанавливается через refresh token; пароль не сохраняется. Сетевые запросы начинаются только после первой отрисовки окна.

## Окно облачных сохранений

Одна таблица показывает все сохранения этого ПК и облака. Колонки «На ПК» и «В облаке» явно отмечают, где лежит запись; бейдж «Состояние» объясняет связь (подробности — во всплывающей подсказке):

| Состояние | Значение |
|---|---|
| Синхронизировано | версии на ПК и в облаке совпадают |
| Только на ПК / Только в облаке | копии на другой стороне нет |
| Изменено на ПК / Изменено в облаке | одна сторона новее другой |
| Конфликт версий | запись изменена на обеих сторонах после последней синхронизации |
| Уже есть в облаке | несвязанные сохранения одного режима с тем же именем, но разными параметрами |
| Удалено из облака / Удалено на ПК | связанная копия удалена с одной стороны |
| Не поддерживается | запись другого формата или более новой версии приложения |

Совпадающие по содержимому несвязанные записи связываются автоматически и сразу показываются как синхронизированные. Из окна фрактала заранее выбран фильтр его режима; его можно снять. Есть также поиск и фильтр по состоянию со счётчиками.

**Действия со всем списком** (плитки сверху) применяются к записям, показанным с учётом фильтров; на плитках видно, сколько записей будет передано и сколько потребуют выбора:

- **«Синхронизировать всё»** — отправляет новое и изменённое на ПК, получает новое и изменённое в облаке.
- **«Отправить всё в облако»** — только в сторону облака.
- **«Получить всё на ПК»** — только в сторону ПК. Заменённые локальные файлы и их превью уходят в Корзину.

Массовые действия никогда не перезаписывают более новую версию на другой стороне (такие записи учитываются в отчёте) и не отменяют удаления.

**Действия с отмеченными записями.** Галочки в первой колонке (и Shift/Ctrl) выбирают часть записей; флажок в заголовке отмечает все показанные. Для отмеченных доступны «Отправить», «Получить», «Переименовать» (на ПК и в облаке сразу для синхронизированной записи) и «Удалить из облака» с подтверждением прямо в нижней панели. Для явно отмеченных записей спорные случаи — более новая версия на другой стороне, удалённая копия — не пропускаются, а выносятся на выбор.

**Коллизии.** Если передача может потерять или задублировать версию, открывается диалог с обеими сторонами и таблицей отличающихся параметров:

- **«Сохранить обе версии»** — версия с ПК переименовывается с префиксом (по умолчанию «Копия · », можно изменить; при совпадении добавляется номер), облачная запись при этом никогда не меняется. Дальше действует направление операции: отправка загружает переименованную копию новой записью, получение скачивает облачную версию под исходным именем, синхронизация делает и то и другое.
- **«Оставить версию с этого ПК»** — условный PUT с текущей revision перезаписывает облачную запись.
- **«Взять версию из облака»** — локальный файл заменяется, прежний уходит в Корзину.
- **«Отправить/Скачать снова»** — для записей, удалённых с одной стороны.
- **«Пропустить»** и **«Остановить всё»**.

Флажок «Применить к остальным таким же случаям» повторяет выбор для коллизий того же вида до конца операции. Если условный PUT встречает параллельное изменение (409), обе стороны перечитываются и выбор запрашивается заново, без повтора запомненного решения.

Операции запускаются только вручную и не работают в фоне. Прогресс и кнопка «Остановить» находятся в строке состояния; остановка срабатывает после текущей записи и не откатывает уже выполненные шаги. Список при передаче не блокируется.

Облачные данные появляются в обычном менеджере сохранений соответствующего фрактала. Превью не отправляются и не скачиваются. Для их создания выберите сохранение в обычном менеджере и нажмите **«Рендер превью»**. После обновления параметров устаревшее локальное превью перемещается в Корзину; при переименовании превью переезжает вместе с файлом.

Совпадающее имя не является идентификатором записи. Связь с облаком хранится по GUID, revision и SHA-256 локального JSON. Перед каждым действием обе стороны записи перечитываются; если локальный файл изменился во время операции, действие не выполняется.

Удаление из облака требует текущую revision. Локальные копии остаются, связь сохраняется как отметка удаления, поэтому массовые операции запись не воскрешают. Чтобы восстановить её в облаке, отметьте запись и нажмите **«Отправить»**. Чтобы вернуть удалённую локальную копию, отметьте запись и нажмите **«Получить»**.

Если связь оборвалась во время отправки, обновите список (F5) перед повтором: сервер мог уже принять запрос. API не предоставляет ключ идемпотентности для POST. Неизвестные форматы и повреждённые записи учитываются в отчёте и не импортируются.

## Безопасность подключения

Адрес сервера не хранится в исходниках. Скопируйте `cloud-connection.example.json` в `cloud-connection.local.json` в каталоге WPF-проекта и укажите свой HTTPS-адрес. Локальный файл исключён из Git и копируется рядом с приложением при сборке и публикации. Приоритет имеет пользовательский `Settings/cloud-connection.json` в каталоге данных приложения. Без настройки облако покажет сообщение с инструкцией; остальные функции приложения работают как обычно.

Публичный корень Caddy встроен в сборку из `Assets/Certificates/fractalcloud-caddy-root.crt`. Приватные ключи сервера в приложение не включены. IP, SSH-реквизиты и серверные пути не следует добавлять в исходники и общую документацию. Локальный файл подключения содержит реальный адрес, поэтому его нужно учитывать при передаче готовой сборки другим людям.

.NET проверяет TLS через `SslClientAuthenticationOptions.CertificateChainPolicy` с `CustomRootTrust`: доверяется только этому корню, проверяются имя/IP сервера, цепочка, назначение и сроки сертификата. Callback, принимающего сертификаты, нет; перенаправления HTTP отключены. Для частного CA Caddy отсутствует CRL/OCSP, поэтому проверка отзыва для этого подключения не выполняется. Доверие не добавляется глобально в Windows. См. [документацию Microsoft](https://learn.microsoft.com/en-us/dotnet/api/system.net.security.sslclientauthenticationoptions.certificatechainpolicy?view=net-10.0).

Access token находится только в памяти. Refresh token и идентификатор аккаунта зашифрованы Windows DPAPI (`CurrentUser`, entropy привязана к серверу); шифротекст находится в `Settings/cloud-*.dpapi` в каталоге данных приложения. Его нельзя переносить на другой ПК для входа. На каждом ПК вход выполняется отдельно. **«Выйти»** удаляет локальный сеанс; серверного endpoint отзыва токенов в данном контракте нет. Пароли и токены не передаются в журнал и не выводятся в текст ошибок.

Клиент проверяет expiresIn с небольшим запасом. Запросы авторизации и API сериализованы одним semaphore, поэтому refresh не выполняется параллельно. При 401 — ровно один refresh и один повтор; неуспешный refresh удаляет локальные токены и возвращает форму входа. Ошибка обычного запроса без refresh не удаляет сеанс.

## Домен и публичный сертификат

После настройки домена и Let's Encrypt создайте `%LOCALAPPDATA%\Fractal Explorer Studio\Settings\cloud-connection.json`:

```json
{
  "Server": "https://your-domain.example:9443",
  "UseCaddyRoot": false
}
```

Перезапустите приложение. Будет применяться стандартное системное доверие TLS, потребуется вход для нового адреса. Индекс синхронизации изолирован по серверу и email; одинаковые неизменённые записи при первой синхронизации сопоставляются по содержимому, а отличающиеся сохраняются раздельно. При смене частного корня нужно обновить встроенный публичный сертификат после проверки его происхождения.

## Формат и ограничения

Контракт API не изменён. `jsonData` передаётся **строкой**, содержащей JSON-объект `{"format":"FractalExplorerWPF","version":1,"category":"Mandelbrot","state":{...}}`. `state` содержит обычные параметры WPF-сохранения и `SaveFormatVersion`, включая встроенную в сохранение палитру, когда она поддерживается моделью. Файлы палитр, PNG, пути и настройки входа не включаются. Название — до 100 символов, вся строка jsonData — до 1 МиБ UTF-8. Форматы других клиентов не импортируются автоматически.

Индекс `Settings/cloud-sync-<hash>.json` не содержит секретов и разделён по адресу сервера и email. Рядом лежит одноразовый кэш `Settings/cloud-remote-<hash>.json`: режим, хэш содержимого и причина несовместимости для каждой уже просмотренной revision. Список API возвращает только метаданные, поэтому без кэша каждое обновление скачивало бы все несвязанные записи; удалённый кэш просто строится заново. Новый облачный слой не изменяет форматы существующих локальных сохранений. Сервер, база, служба, VPN и порты 443/8443 не меняются.

## Проверка

```powershell
dotnet build .\FractalExplorerWPF\FractalExplorerWPF\FractalExplorerWPF.slnx
dotnet run --project .\FractalExplorerWPF\Verification\SavePreviewVerification.csproj -- cloud
dotnet run --project .\FractalExplorerWPF\Verification\SavePreviewVerification.csproj -- manager
dotnet run --project .\FractalExplorerWPF\Verification\SavePreviewVerification.csproj -- cloud-live
```

`cloud` использует поддельный API, временные данные, настоящий DPAPI и локальный TLS-сервер. Проверяются обновление/ротация токенов, очередь конкурентных запросов, лимит повтора 401, expiresIn, лимиты JSON, состояния таблицы, «Отправить/Получить/Синхронизировать всё», отказ массовой отправки перезаписывать более новую облачную версию, совпадение имён с префиксом и переносом превью, замена через Корзину, «Применить ко всем», конфликты с гонкой PUT, автоматическая связь одинаковых записей, удаления и их восстановление, переименование, чужой формат, изоляция аккаунтов, запрет обхода пути, окна XAML и отказ TLS для неверного имени, неизвестного корня и просроченного сертификата.

`cloud-live` выполняет только GET `/` и анонимный GET `/api/saves` на VPS: проверяет реальный сертификат и ожидаемый 401. Для проверки полного цикла с реальной учётной записью войдите из приложения на двух ПК, создайте тестовое сохранение, синхронизируйте, измените его на обоих ПК и выберите «Сохранить обе версии». Создайте на двух ПК разные сохранения с одним именем и проверьте «Уже есть в облаке», отправку с префиксом и «Применить к остальным». Также проверьте переименование, отмену операции, повторный запуск приложения и удаление тестовых облачных записей.
