Physarum 3D (`Fractal3D:Physarum3D`) входит в общий обход каталога; панель агентов встроена в 3D-окно, подготовка завершается первым опубликованным кадром.

Фигуры Лихтенберга (`Fractal3D:Lichtenberg3D`) автоматически входят в обход каталога; панель роста встроена в общее 3D-окно.

Расслоение Хопфа (`Fractal3D:Hopf`, `fractal3d-hopf`) автоматически входит в обход каталога; его редактор встроен в общее 3D-окно.

# Генератор скриншотов окон WPF

Gray–Scott 3D, узоры Тьюринга 3D и Кан–Хиллиард 3D входят в общий обход каталога. Ожидание кадра учитывает подготовку
объёмного поля и его публикацию; отдельных окон редакторов у этих режимов нет.

Консольный инструмент, который открывает каждое окно WPF-приложения (по одному
за раз, далеко за пределами экрана — пользователь их не увидит) и сохраняет
его как PNG с настоящей рамкой Windows. Написан для того, чтобы один раз
пересобрать полный набор скриншотов для README/документации без ручного
обхода всего каталога. Полный набор охватывает 91 пункт
каталога, их редакторы и общие диалоги. Витрина находится в корневом
`README.md`, полная галерея с подписями — в `Pictures/WPF/README.md`.

## Когда использовать

- Нужно (пере)сгенерировать скриншоты для README после заметных визуальных
  изменений — новая тема оформления, обновлённая раскладка, новое окно/фрактал/
  лаборатория, новый общий редактор палитры или параметров.
- Нужен быстрый визуальный обзор всех окон приложения (например, перед
  релизом) без открытия каждого вручную.

Инструмент не входит в решение `FractalExplorerWPF.slnx` — собирайте и
запускайте его отдельно.

Режим `SnowCrystal` включён в полный обход каталога: окно роста снежных
кристаллов (`snow-crystal`) снимается после пятнадцати секунд живого роста.
Для 2D DLA ожидание роста составляет двенадцать секунд.
Отдельных редакторов у него нет; цвета выбираются общим диалогом.

## Запуск

Режим `TuringPatterns` включён в полный обход: окно узоров (`turing-patterns`)
и общий редактор палитр с отдельной библиотекой (`turing-palette-editor`).

Из корня репозитория:

```powershell
dotnet build .\FractalExplorerWPF\ScreenshotGen\ScreenshotGen.csproj
dotnet run --project .\FractalExplorerWPF\ScreenshotGen\ScreenshotGen.csproj -- .\Pictures\WPF
```

Первый аргумент — папка вывода (создаётся, если её нет; существующие файлы с
такими же именами перезаписываются). Второй необязательный аргумент `smoke`
запускает только 4 быстрых скриншота (каталог, быстрый переключатель, «О
программе», классический Мандельброт) — используйте его, чтобы проверить,
что инструмент вообще работает, прежде чем ждать полный прогон (весь каталог,
несколько минут).

```powershell
dotnet run --project .\FractalExplorerWPF\ScreenshotGen\ScreenshotGen.csproj -- .\Pictures\WPF smoke
```

Для обновления одного пункта и его редакторов используйте ключ `LaunchKey`
из `Models/FractalCatalog.cs`, например:

```powershell
dotnet run --project .\FractalExplorerWPF\ScreenshotGen\ScreenshotGen.csproj -- .\Pictures\WPF --only=Ikeda
```

`--only` не совмещается со `smoke`; неизвестный ключ возвращает код 2.
Снимок Икэды использует `u = 0.9` и центр `(0.65, -0.65)`, чтобы показать
хаотический аттрактор целиком. При исходном `u = 0.918` выбранная затравка
сходится к неподвижной точке за пределами начального кадра. Параметры
самого приложения этот инструмент не меняет.

## Как это работает

- **Настоящий `App`, а не голый `Application`.** Просто `new Application()`
  не подключает `Theming/ThemeStyles.xaml` и активную тему — без них не
  находятся стили типа `FractalPanelToggleButtonStyle`, которые использует
  почти каждое окно. Поэтому инструмент создаёт `FractalExplorerWPF.App`,
  вызывает `InitializeComponent()` и `ThemeManager.Initialize(app)` напрямую,
  не вызывая `Run()` — событие `Startup` (которое создало бы реальное
  `MainWindow` и показало его пользователю) так и не срабатывает.
- **Свой каталог данных.** До создания окон вызывается
  `AppPaths.OverrideDataRoot(<bin>/ScreenshotData)`: скриншоты не зависят от
  сохранений, палитр и выбранной темы пользователя в AppData и не пишут туда.
- **Подмена `Application.ResourceAssembly`.** `pack://application:,,,/...`
  по умолчанию резолвится в сборку .exe (`ScreenshotGen`), а превью и другие
  ресурсы зашиты в `FractalExplorerWPF.dll`. Публичный сеттер свойства к
  этому моменту уже недоступен (платформа сама выставляет значение при
  первом обращении), поэтому инструмент подменяет закрытое поле через
  reflection (`ForceResourceAssembly`).
- **Окна открываются далеко за экраном.** `WindowStartupLocation = Manual`,
  `Left`/`Top` — с большим отрицательным смещением, `ShowInTaskbar = false`.
  DWM всё равно выполняет полный layout и рендер, просто ничего не видно на
  реальном мониторе.
- **Захват — склейка PrintWindow и RenderTargetBitmap.** Голый `PrintWindow`
  на окне, стоящем далеко за экраном, отдаёт только рамку и заголовок —
  композитная поверхность WPF-контента там не обновляется и получается
  белой. Поэтому рамка/заголовок берутся через `PrintWindow`
  (`PW_RENDERFULLCONTENT`), а содержимое клиентской области — надёжным
  `RenderTargetBitmap` (он всегда корректно рендерит визуальное дерево
  независимо от положения окна на экране), и оба изображения склеиваются в
  одно по смещению `ClientToScreen`.
- **Ожидание конца рендера.** Многие окна выставляют приватное поле
  `_isRendering` на время расчёта кадра (частый паттерн в проекте). Фиксированной
  паузы не всегда достаточно — например, Nova Mandelbrot мог сняться раньше,
  чем движок закончил кадр. `WaitForRenderIdleAsync` через reflection ждёт,
  пока флаг не станет `false` (с разумным пределом на случай окон без такого
  поля или с непрерывной симуляцией — Gray–Scott, DLA, Flame, Буддаброт).
  `DynamicSystemWindow` использует поле `_rendering`; учитывается также
  отложенный запуск через `_timer`. Ожидание ограничено 30 секундами:
  превышение считается ошибкой захвата, чтобы не сохранять пустой кадр.
  У окон с живым превью (`Fractal3DWindow`) кадр считается лесенкой — черновик,
  полный кадр, сглаживание, — и между ступенями `_isRendering` ненадолго гаснет,
  поэтому ожидание учитывает и приватное `_frameRequested`: пока стоит запрос
  следующей ступени, снимать рано.
- **«Уникальные инструменты» каждого окна** (редакторы палитр, редакторы
  трансформаций, выбор параметров) открываются либо прямым конструированием с
  аргументами, добытыми через reflection из приватных полей уже открытого
  окна (`_paletteManager`, `_transforms` и т.п.), либо, для окон с приватным
  конструктором и статическим модальным `Open(...)` (`SaveManagerWindow`,
  `ImageExportManagerWindow`), — через `CaptureModalAsync`: до вызова
  модального метода в очередь диспетчера кладётся задача, которая находит
  новое окно в `Application.Current.Windows`, ждёт, снимает скриншот и сама
  его закрывает, позволяя `ShowDialog()` вернуться.

## Поддержка при изменениях в приложении

Облачные окна `CloudSaveManagerWindow` (таблица на вымышленных записях всех состояний — `00-cloud-saves`, форма входа — `00-cloud-login`) и `CloudConflictWindow` (совпадение имени — `00-cloud-conflict`) включены в полный набор. Менеджер создаётся с `connectOnLoad: false` и заполняется через внутренний `ShowEntriesForPreview` (сборка приложения открывает internals для `ScreenshotGen`); подключение к VPS и ввод реальных учётных данных при создании скриншотов не выполняются.

Все одиннадцать режимов `BasinExplorerWindow` входят через ключи `Basins:` каталога, включая
комплексную логистическую карту, магнитный маятник, систему притягивающих центров,
градиентный спуск, комплексный градиентный поток и полиномиальные векторные поля.
Редактор физических центров встроен в основное окно; отдельного диалога нет.
Физические модели, оптимизация и непрерывные потоки по умолчанию используют быстрый предпросмотр в треть разрешения;
ожидание `_isRendering` применяется к ним так же, как к остальным бассейнам.

Все виды `Fractal3DWindow` (21 режим) входят через ключи `Fractal3D:` каталога
(`fractal3d-<вид>`). Кадр считает видеокарта. Менеджер палитр
(`fractal3d-palette-editor`) общий для семи исходных видов, поэтому снимается
один раз — на Мандельбульбе, через приватные `_paletteManager` и `_palette`;
третьим аргументом конструктора передаётся `null`, и предпросмотр фрактала
внутри менеджера не считается — иначе снимок зависел бы от того, успела ли
видеокарта посчитать кадр к моменту захвата. Отдельный редактор IFS
(`ifs3d-palette-editor`) снимается на конструкторе объёмных IFS и использует
свою библиотеку палитр. Там же снимается редактор преобразований
(`ifs3d-transform-editor`) с настройкой случайной генерации. Автовращение
по умолчанию выключено, поэтому окно успокаивается само и снимок получается
с полным кадром. Без
Direct3D 11 окно покажет ошибку рендера — скриншоты снимаются на машине
с рабочим драйвером.

Объёмный DLA входит автоматически через пункт `Fractal3D:Dla3D` (`fractal3d-dla3-d`).
По умолчанию показывается готовый коралл; наблюдение роста начинается только кнопкой,
поэтому обычное ожидание завершения кадра подходит и этому режиму.

Список окон и их «уникальных инструментов» — это набор `case`-веток в
`ProcessCatalogItemAsync` (для пунктов каталога, `Models/FractalCatalog.cs`)
плюс несколько прямых вызовов в начале `RunAllAsync` (общие служебные окна).
Режим `Popcorn` снимается отдельно как `popcorn`, а его редактор палитр — как
`popcorn-palettes`; используются собственные готовые формы и палитры Popcorn.
Режим `Hopalong` снимается как `hopalong`, его редактор палитр — как
`hopalong-palettes`; основное окно открывает Hopalong Мартина напрямую.
Генератор Спротта (`SprottQuadratic`) снимается как `sprott-quadratic` через
`DynamicSystemWindow(DynamicSystemKind.Attractors2D, Attractor2DKind.SprottQuadratic)`;
это отдельный пункт каталога, а не значение `DynamicSystemKind`.
Объёмный IFS входит через ключ `Fractal3D:Ifs3D` и снимается после первого рендера.
При добавлении, удалении или переименовании WPF-окна, каталожного пункта или
общего диалога — обновите соответствующую ветку здесь так же, как обновляете
таблицы окон в `CLAUDE.md`/`AGENTS.md`. Если у нового окна есть кнопка,
открывающая ещё одно окно (палитра, редактор параметров), которое стоит
попадания в скриншоты, — добыть нужные аргументы конструктора можно через
`GetMember(parentWindow, "_названиеПоля")` по образцу уже существующих веток.

Ландшафты входят через `Fractal3D:Terrain` и автоматически снимаются как `fractal3d-terrain`. Настройки рельефа и экспорт карты высот встроены в общее 3D-окно; отдельного окна не добавлено.

Объёмный Flame входит через `Fractal3D:Flame3D`; его редактор `flame3d-transform-editor` создаётся из `_flameTransforms` основного окна. Цвет задаётся слоями редактора, отдельного окна палитр для Flame нет.


Пространственные L-системы входят автоматически через `Fractal3D:LSystem3D` и снимаются как `fractal3d-l-system3-d`. Редактор `LSystem3DEditor` встроен в общее 3D-окно; отдельного окна параметров нет. Графические регуляторы ниже правил можно снять дополнительным прокручиванием панели. Проверка `lsystem3d` создаёт изображения редактора и трёх углов отдельно.

Генераторы L-систем снимаются отдельно: `lsystem-randomizer-2d` и `lsystem-randomizer-3d`. Их настройки открываются кнопкой из соответствующего исследователя; содержимое общее, пространственные параметры доступны только в 3D.

Полный успешный прогон заканчивается строкой `DONE: ok=<число снимков> fail=0`; `smoke` —
`DONE: ok=4 fail=0`. При ошибке открытия, рендера или захвата инструмент
возвращает ненулевой код выхода. После обновления смотрите изображения:
сам факт создания PNG не подтверждает качество живой симуляции или настройки кадра.

Буддаброт 4D входит автоматически через Fractal3D:Buddhabrot4D (fractal3d-buddhabrot4-d). Редактор проекции встроен в общее окно; отдельного диалога нет. Настройки орбит свернуты по умолчанию; кадр ожидается тем же общим механизмом.
