# Проверка превью сохранений WPF

Из корня репозитория:

```powershell
dotnet build .\FractalExplorerWPF\FractalExplorerWPF\FractalExplorerWPF.slnx
dotnet run --project .\FractalExplorerWPF\Verification\SavePreviewVerification.csproj
dotnet run --project .\FractalExplorerWPF\FractalExplorerWPF\FractalExplorerWPF.csproj
```

Проверка использует искусственный кадр и скрытые, не показанные WPF-контролы. Она не захватывает экран и не проверяет визуальное копирование полотна. Проверяются отсутствие автоматического рендера, запись/чтение PNG, прогресс, отмена, запоздалые результаты, ошибка вычислений, повреждённый PNG, отсутствие кадра, точки интереса и численный рендер на глубоком зуме — Мандельброт, Коллатц, Феникс и Nova, а также примитивы произвольной точности под ними (корень, экспонента, тригонометрия, логарифм, комплексные логарифм и степень). Временные сохранения создаются только рядом с исполняемым файлом проверочного проекта и удаляются после проверки.

## Ручная проверка

Запуск через `dotnet run` использует новую Debug-сборку. Ранее опубликованный exe в `bin/Release/.../publish/` этими командами не обновляется. Приложение ищет каталог `Saves` рядом со своим exe; для проверки сохранений из другой сборки перенеси их **копию** в каталог `Saves` проверяемой сборки, сохранив резервную копию имеющихся файлов.

1. В окне Мандельброта дождись готового изображения. Открой менеджер и сохрани состояние под новым именем. Превью должно сразу показать тот же вид с сохранением пропорций, без повторного вычисления, кнопок и индикаторов основного окна. Закрой и открой менеджер: картинка должна сохраниться.
2. Сохрани два заметно разных вида, включая смещение/масштабирование. Переключай записи: каждая должна сразу показывать собственную картинку, без прогресса рендера. Проверь также вытянутое окно и сглаживание основного кадра.
3. Для тестовой записи при закрытом менеджере убери её PNG из `Saves/SavePrevData/<режим>/`. При выборе записи должна появиться надпись об отсутствии превью. Другой кадр оставаться не должен; вычисления не запускаются. Отдельно проверь повреждённый PNG.
4. Выбери старые «hq1», «hq2», «предел». Старое чёрное превью остаётся до явного нажатия «Рендер превью». После нажатия должны появиться процент, время и кнопка «Отмена»; после завершения — изображение и сообщение об обновлении. Для «предел» используются сохранённые 4500 итераций. При следующем открытии показывается новый PNG без вычислений.
5. Запусти повторный пересчёт записи с готовым PNG и нажми «Отмена». Дождись сообщения об отмене: прежнее изображение должно остаться. Проверь повторный запуск. Затем во время расчёта переключись на другую запись: новый рендер сам не запускается, старый результат не появляется поверх новой записи. Проверь также закрытие менеджера во время рендера.
6. Перезапиши тестовое сохранение другим текущим видом основного окна. Превью должно соответствовать новому виду сразу и после повторного открытия менеджера. Удаление тестовой записи должно удалить связанный PNG.
7. Переключись на «Точки интереса». Выбор не запускает вычислений; кнопка ручного рендера доступна. Выполненное превью сохраняется в отдельном подкаталоге `PointsOfInterest` и используется при повторном выборе.
8. Повтори сохранение текущего кадра в других используемых режимах: например, Ньютон, Flame, динамические системы, Gray–Scott. Для анимации/незавершённого рендера сохраняется видимый на момент нажатия кадр. Для Gray–Scott ручной пересчёт строит новую симуляцию из сохранённых параметров (900 шагов); состояние концентраций симуляции в JSON не хранится. Точный вид текущей симуляции сохраняется именно в PNG-снимке.

Захват использует WPF-слои приложения, а не системный скриншот: перекрывающее полотно окно менеджера не должно попадать в PNG.
